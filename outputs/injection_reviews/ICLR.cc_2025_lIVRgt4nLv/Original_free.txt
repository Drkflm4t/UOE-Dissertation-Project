This paper presents Agent S, an open framework for desktop GUI agents that aims to “use computers like a human.” The core proposal combines three ingredients: an experience-augmented hierarchical planner, a continual memory mechanism with narrative and episodic memories updated through self-evaluation, and an Agent-Computer Interface (ACI) that uses screenshots plus an augmented accessibility tree and exposes a bounded set of high-level actions. The paper evaluates the system primarily on OSWorld and additionally on WindowsAgentArena, reporting a substantial improvement over prior baselines and claiming a new state of the art on OSWorld.

Overall, I found the paper timely, practically relevant, and reasonably well executed. The problem setting—general-purpose desktop control through GUI interaction—is important and increasingly central to agent research. The paper’s main strength is that it does not rely on a single trick, but instead proposes a coherent systems design that addresses several known bottlenecks in GUI agents: long-horizon planning, grounding, and adaptation to application-specific knowledge. The empirical gains on OSWorld are meaningful, and the ablations suggest that the proposed components each contribute. I also appreciate that the authors release code and evaluate on a second benchmark in a different operating system. At the same time, the paper is more of a strong systems integration paper than a fundamentally new algorithmic advance, and several methodological details and evaluation choices limit how strongly I can assess the claims. In particular, the continual learning setup, the fairness of comparisons, and the exact contribution of each component deserve more careful treatment.

The technical framing is clear. The overview figure on page 4 is helpful: the Manager retrieves web knowledge and narrative memory to produce subtasks, Workers retrieve episodic memory to execute each subtask, and a self-evaluator summarizes trajectories back into memory. The distinction between narrative memory for high-level task summaries and episodic memory for subtask-level action guidance is intuitive and well motivated. Likewise, the ACI design is sensible. The discussion on pages 6–7 about why raw pixel-only grounding and unconstrained code actions are mismatched to current MLLM capabilities is convincing. The dual-input design—using screenshots for semantic understanding and an accessibility tree augmented with OCR for grounding—seems like a practical and effective compromise. The bounded action space in Table 5 on page 15 also appears well chosen for desktop control.

The empirical results on OSWorld are promising. In Table 1 on page 8, Agent S with GPT-4o improves overall success from 11.21% to 20.58%, with especially large gains in Daily and Professional tasks. The bar chart on page 2 and the detailed table on page 8 both support the claim that improvements are broad rather than isolated to one category. The WindowsAgentArena result in Table 4 on page 10 is also encouraging as a cross-OS sanity check, though the gain there is smaller and somewhat uneven across domains. The qualitative examples in the appendix are useful: the successful trajectories on pages 18–20 show that the system can indeed carry out multi-step workflows across applications, while the failure cases on pages 22–23 help ground the error taxonomy.

That said, I have several concerns about the strength of the experimental evidence. First, the main comparisons are against benchmark-reported baselines rather than against stronger reimplementations or matched ablations under identical prompting, inference budgets, and tool interfaces. This matters because Agent S changes multiple aspects at once: planning, memory, retrieval, action space, grounding representation, and likely prompting structure. The paper acknowledges that the WindowsAgentArena strongest model is inaccessible, but on OSWorld the comparison still mixes architectural and interface changes. In particular, the ACI itself appears to be a major intervention, and Figure 6 on page 9 suggests that ACI alone already improves over the baseline. This makes it difficult to isolate whether the gains primarily come from better agent architecture or from a more favorable interface abstraction. The paper does include ablations, but because they are run on a 65-example subset rather than the full benchmark, the conclusions are somewhat less definitive.

Second, the continual memory update setup raises evaluation questions. The paper states on pages 5–6 that Agent S continually updates memory “even during inference” as it encounters new tasks. If the benchmark evaluation proceeds sequentially and the agent is allowed to accumulate experience from earlier test tasks that can help later test tasks, then the reported numbers are not directly comparable to standard static-test evaluation unless the baseline is given an analogous opportunity. This is especially important because OSWorld contains repeated applications and recurring task motifs. The paper should be much more explicit about whether memory is updated across test episodes, whether task order is fixed, whether multiple runs with different orders were tested, and whether any benchmark leakage could occur through environment-aware exploration tasks or web retrieval. The current description leaves too much ambiguity for a top-tier evaluation claim.

Third, the initial memory construction procedure may blur the line between training and evaluation. On page 6, the authors describe self-supervised exploration using environment-independent tasks and “environment-aware tasks” generated from the initial environments of OSWorld and WindowsAgentArena tasks. This is potentially problematic. If the exploration phase uses benchmark initial states to generate related tasks, then the agent may effectively pre-adapt to the test distribution in a way that is stronger than zero-shot evaluation. Even if no ground-truth labels are used, this still constitutes benchmark-specific pre-exposure. The paper should clarify exactly how these exploration tasks are generated, whether they are derived from test instances, and whether a strict separation between memory-building environments and evaluation environments is maintained. Without this clarification, the “state-of-the-art” claim is harder to interpret.

Fourth, the paper’s notion of self-evaluation is interesting but under-validated. The self-evaluator determines whether trajectories are successful enough to store and summarizes them into textual rewards. However, there is little analysis of evaluator accuracy, false positives, or memory contamination. Since the system learns from its own inferred successes and failures without external supervision, one key risk is reinforcing incorrect strategies. The ablation in Figure 7 on page 9 suggests that summarized experiences help, but this does not tell us whether the evaluator is reliable or merely useful on average. A stronger paper would include at least a small manual audit of stored memories, evaluator precision/recall on success detection, or examples where self-evaluation goes wrong.

Fifth, the paper would benefit from more rigorous reporting of statistical uncertainty and computational cost. The benchmark sizes are not huge, and some category-level differences may be noisy. Confidence intervals or bootstrap estimates would help. More importantly, the proposed system adds web search, multiple retrieval calls, hierarchical planning, reflection, and memory updates. This likely increases latency and token cost substantially. The authors themselves note in the conclusion that step count and wall-clock time are unaddressed. Given that practical desktop agents are highly sensitive to latency, this omission is significant. A method that doubles success rate at 10x cost may still be valuable, but readers need that tradeoff quantified.

On the methodological side, I liked the conceptual decomposition into Manager and Worker, but some parts remain underspecified. For example, how exactly are subtasks represented? How often does replanning occur after FAIL? What prompts are used for the Experience Context Fusion and Trajectory Reflector modules? How are retrieval candidates ranked and truncated? How large are the narrative and episodic memories, and how does performance scale with memory size? The formulas on pages 5 and 16–17 are high-level and mostly schematic rather than operational. For reproducibility and scientific clarity, more concrete implementation detail is needed in the main paper or appendix.

The error analysis is a positive aspect, but it could go further. Table 3 on page 10 shows execution errors dominate, followed by grounding errors, and the pie chart on page 21 attributes 46% of execution errors to planning or grounding. This is useful, but the taxonomy is somewhat overlapping: execution errors often seem to be downstream manifestations of planning or grounding failures. A more causal analysis would be stronger, for example separating first-failure causes from propagated failures, or measuring recovery ability after an initial mistake. The failure examples on pages 22–23 are informative and support the claim that grounding remains brittle, especially when accessibility-tree IDs or screen regions are misleading.

I also want to note a few presentation issues. The paper is generally readable, but there are several places where the writing could be tightened. Some claims are overstated relative to the evidence, especially phrases like “uses computers like a human,” which is rhetorically appealing but scientifically imprecise. There are also minor inconsistencies and typos: for example, some notation around episodic versus narrative experience is a bit confusing across pages 4–5 and 16–17, and the references include what appears to be a duplicated AutoGuide citation. The appendix tables are useful, but some detailed per-app results in Table 8 on page 16 are surprising—for instance, Agent S underperforming the baseline on Calc while doing much better overall—and deserve discussion in the main text.

In terms of novelty, I would characterize the contribution as a thoughtful integration of known ideas—hierarchical planning, retrieval augmentation, memory, reflection, accessibility-tree grounding, OCR augmentation, and constrained action spaces—into a strong desktop-agent framework. The novelty lies less in any single component and more in the particular combination and the empirical demonstration that this combination works better than prior baselines. That is a legitimate contribution for a systems-oriented ML paper, but the paper should be careful not to oversell individual modules as fundamentally new. For example, the “textual rewards” framing is evocative, but in practice this is closer to self-generated trajectory summarization for retrieval than to reinforcement learning in a formal sense.

My main suggestions for improvement are as follows. First, clarify the evaluation protocol around memory construction and continual updates, especially whether benchmark test tasks or their initial states are used during exploration and whether memory persists across test episodes. Second, add stronger controlled comparisons on the full OSWorld benchmark, ideally including a baseline with the same ACI but without hierarchical memory/retrieval, and a version with retrieval but frozen memory. Third, report cost metrics: average steps, wall-clock time, token usage, and web-search overhead. Fourth, provide a more careful analysis of self-evaluator quality and memory noise. Fifth, include uncertainty estimates and, if possible, multiple evaluation orders for continual-update experiments. These additions would substantially strengthen the paper.

Despite these concerns, I think the paper makes a meaningful contribution. The problem is important, the system design is sensible, the empirical gains are nontrivial, and the paper includes useful ablations and qualitative analysis. My overall assessment is positive but not unreservedly so: I believe this is a strong applied/agent-systems paper whose claims would be much more convincing with tighter evaluation protocol and clearer separation between training-like memory accumulation and test-time generalization.

Recommendation: weak accept.

The strongest reasons in favor are the practical importance of the problem, the coherent architecture, and the sizable gains on OSWorld. The strongest reasons against are ambiguity in the continual-learning evaluation setup, possible benchmark-specific pre-exposure through exploration, and limited isolation of which components truly drive the gains. If the authors address these issues in revision, the paper would be significantly stronger.
