Summary: The paper formalizes auditing black-box LLM APIs as a two-sample hypothesis testing problem, termed Model Equality Testing, where one tests whether an API distribution matches a reference model distribution or a prior snapshot of the same API. The main proposal is to use MMD-based kernel two-sample tests, especially a simple Hamming string kernel over completions, arguing that this kernel is sample-efficient in high-dimensional sequence spaces. Through simulations on Wikipedia continuation, HumanEval, and UltraChat-style tasks, the authors compare several kernels and classical multinomial tests under distortions such as quantization, watermarking, finetuning, and model substitution. They report that the Hamming-MMD test achieves strong empirical power with relatively few samples and then apply it to 31 commercial Llama API endpoints across multiple providers, finding that 11 endpoints differ from fp32/fp16 reference distributions. The paper also uses estimated MMD values as an effect-size notion to compare models and providers.

Strengths: Timely and practically important problem: auditing black-box LLM APIs for undisclosed distribution shifts is highly relevant for reproducibility, benchmarking, and user trust.; Clear problem formulation as a statistically grounded two-sample testing task, with explicit null/alternative hypotheses and type-I error considerations.; Strong empirical breadth: the paper evaluates quantization, watermarking, finetuning, model swaps, and commercial API endpoints across multiple model families and prompt distributions.; The proposed Hamming-kernel MMD test is simple, computationally lightweight, and empirically effective relative to stronger but less sample-efficient universal kernels and classical multinomial tests.; The paper goes beyond binary testing by using MMD estimates as a distance/effect-size proxy, enabling informative comparisons among models and providers.; Useful practical artifacts: open-source package and a large released dataset of completions improve reproducibility and downstream utility.; The appendix is extensive and includes ablations on prompt count, completion length, permutation testing, asymmetric sampling costs, and approximate goodness-of-fit baselines.

Weaknesses: The central method is largely empirical and heuristic: the preferred Hamming kernel is explicitly non-injective, so the test cannot in principle detect all distribution differences, and the paper offers limited theory explaining when it should be optimal or near-optimal.; The main API audit conclusions may be confounded by uncontrolled implementation differences beyond model weights, including chat templates, tokenizer/rendering differences, server-side prompt preprocessing, undocumented decoding behavior, safety filters, caching, and system prompts.; The decision rule for the composite null (matching either fp32 or fp16) is conservative and ad hoc; while it controls FPR, it may substantially reduce power and complicates interpretation of failures.; The empirical evaluation relies heavily on pre-collected samples from a limited set of prompt distributions, mostly long-form continuation and a small number of coding/instruction prompts, so external validity to broader real-world workloads is uncertain.; Several headline claims about specific providers serving altered distributions are observational rather than causal; the method detects distributional difference but cannot attribute it specifically to quantization, watermarking, finetuning, or provider misconduct.; The use of average rejection rate over 10 repeated samples with a 0.5 threshold for API failure is unconventional and not fully justified statistically as a calibrated testing procedure.; Correlation with task accuracy is only moderate, limiting the practical interpretability of MMD as a proxy for capability differences.

Methodological Flaws: There is a scientific logic gap between detecting distributional inequality and inferring the cause of that inequality. The paper sometimes rhetorically links failures to quantization/watermarking/provider modification, but the experiments do not isolate these causes for commercial APIs.; The Hamming MMD is only a pseudometric, as acknowledged in Appendix A.1, so zero distance does not imply equality. This weakens any strong semantic interpretation of 'indistinguishable' when the chosen kernel misses structured differences not reflected in token-position marginals.; The proof sketch for composite-null FPR control is acceptable for the stated rejection rule, but the overall API audit pipeline adds repeated sampling and a majority-threshold decision rule across 10 runs; the paper does not provide a formal error-control analysis for this aggregated procedure.; The empirical p-value estimation by repeatedly sampling from a pre-collected finite dataset rather than directly from the true model/API introduces an additional approximation layer. Because all experiments are effectively resampling from cached completions, dependence on dataset coverage and finite-sample support may bias power estimates.; For API comparisons in character space, the mapping from token outputs to decoded strings may blur or distort differences attributable to tokenization and stopping behavior. This is practical, but it changes the tested object from the original token distribution to a decoded-string distribution, which should be stated more prominently as a limitation.; The paper validates power extensively but gives limited calibration evidence beyond reported FPR tables. Given the many experimental choices (kernel, prompt set, character-space conversion, repeated runs, Bonferroni corrections, composite null), stronger end-to-end calibration analysis would be desirable.; Some comparisons may be affected by temporal nonstationarity because API samples were collected over different dates and sometimes multiple days (Appendix B). Thus, provider differences may partially reflect time drift rather than stable endpoint differences at a single time point.
