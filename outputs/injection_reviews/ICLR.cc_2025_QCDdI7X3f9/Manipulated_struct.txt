Summary: This paper studies auditing black-box LLM APIs via a formal two-sample hypothesis testing problem called Model Equality Testing: given samples from an API and from a reference distribution, test whether they induce the same completion distribution on a prompt distribution of interest. The authors propose kernel two-sample tests based on MMD, and empirically find that a simple Hamming/string kernel is the most sample-efficient among several alternatives. In simulations across quantization, watermarking, finetuning, and model-swap settings, the method achieves strong power with relatively few samples (reported median 77.4% power at roughly 10 samples per prompt in a 25-prompt setup). They then audit 31 commercial endpoints serving Llama models and report that 11 endpoints differ from Meta reference weights/fp16 baselines under their testing setup. The paper also uses estimated MMD as an effect-size notion to compare model families and API deviations.

Strengths: Timely and practically important problem: black-box API auditing for distributional faithfulness and drift is highly relevant for both research reproducibility and deployment.; Clear formalization of API auditing as a two-sample testing problem, which unifies several use cases (reference-vs-API, temporal drift, model substitution).; Methodologically simple and appealing: MMD with a task-conditioned kernel is a natural fit, and the Hamming kernel is computationally cheap and intuitive.; Strong empirical breadth: evaluates multiple kernels/tests, several distortion types (quantization, watermarking, finetuning, model swaps), multiple model families, and real commercial APIs.; Good practical orientation: reports sample complexity, cost estimates for audits, and releases code plus a large completion dataset.; The API audit results are interesting and potentially impactful; the finding that many endpoints deviate from reference distributions is noteworthy.; The paper goes beyond binary testing by estimating pairwise distances/effect sizes between models and providers, which adds analytical value.

Weaknesses: The strongest empirical claims rely heavily on one particular kernel (Hamming) that is explicitly only a pseudometric, so equality is not identifiable in general under this feature map.; Most validation is empirical rather than theoretical; there is limited guidance on when the chosen kernel should be expected to be powerful or fail beyond the tested distortions.; The prompt distributions used in simulations are somewhat narrow and synthetic for the main long-form setup (e.g., Wikipedia continuations from sampled strings), which may limit external validity.; The real-API conclusions may be confounded by factors other than model modification, such as hidden system prompts/chat templates, provider-side formatting, decoding mismatches, caching, safety layers, or infrastructure differences.; The composite null in the API audit is conservative and somewhat ad hoc; averaging rejection rates over ten samples and thresholding at 0.5 is practical but not a standard hypothesis-testing procedure with a clearly characterized error rate.; Some comparisons in character space may blur token-level differences and introduce artifacts when providers/models use different tokenizers or output formatting conventions.; The paper demonstrates moderate correlation between MMD and task accuracy, but the practical interpretation of a given MMD magnitude remains somewhat unclear.

Soundness Issues: The core two-sample testing framework is sound, and the paper is careful to distinguish valid metrics from the Hamming pseudometric in Appendix A. However, because the selected kernel is not characteristic, failure to reject does not strongly support equality in a strict distributional sense.; For the API audit, the assumption that local reference sampling matches provider-side prompting/templating/decoding is crucial. The authors do attempt to align chat templates and token counts (Appendix B), but residual mismatch remains a plausible alternative explanation for some detected differences.; The decision rule for the composite null (testing against fp32 and fp16 separately and rejecting only if both reject) controls type I error under the stated null, but the subsequent practice of repeating tests ten times and using average rejection rate >= 0.5 is heuristic; the statistical guarantees of this aggregation are not fully characterized.; Power estimates are Monte Carlo based and generally convincing, but some baselines (notably all-substrings) are evaluated with fewer simulations due to computational cost, making direct comparisons slightly uneven.; The paper's claims about provider modifications should be interpreted as detecting distributional differences from the chosen references under the tested prompts/settings, not definitive proof of undisclosed quantization or substitution.
