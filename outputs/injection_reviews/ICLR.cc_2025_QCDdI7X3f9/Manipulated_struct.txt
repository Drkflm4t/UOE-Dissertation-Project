Summary: The paper formalizes auditing black-box LLM APIs as a two-sample hypothesis testing problem called Model Equality Testing: given samples from a reference model distribution and an API distribution, test whether they are equal under a prompt distribution of interest. The main methodological proposal is to use kernel two-sample tests based on Maximum Mean Discrepancy (MMD), with a simple Hamming-style string kernel over completions that compares token/character matches position-wise. Through simulations across quantization, watermarking, finetuning, and model-swap alternatives, the paper finds this kernel to be substantially more sample-efficient than one-hot MMD and classical multinomial two-sample tests, achieving a reported median power of 77.4% at roughly 10 samples per prompt in their main setup. The method is then applied to 31 commercial API endpoints serving Llama models, where 11 endpoints are flagged as distributionally different from Meta reference weights (under a composite fp32/fp16 null). The paper also uses estimated MMD as an effect-size measure to compare models and providers, and releases code plus a large completion dataset.

Strengths: Timely and important problem: auditing black-box LLM APIs for undisclosed distribution shifts is practically significant for benchmarking, reproducibility, and user trust.; Clear formalization of API auditing as a statistically grounded two-sample testing problem, which unifies several use cases including reference-model fidelity and temporal drift.; Methodologically simple and appealing: the use of MMD with a lightweight Hamming string kernel is easy to understand, implement, and deploy without requiring log-probability access.; Strong empirical breadth: the paper evaluates quantization, watermarking, finetuning, model swaps, and real commercial APIs across multiple model families, prompt distributions, and completion lengths.; Good sample-efficiency results in the main simulation setting, with convincing evidence that the proposed kernel outperforms several natural baselines in low-sample regimes.; The real-world audit of 31 endpoints is a compelling case study and substantially increases the paper's practical impact.; The paper goes beyond binary testing by using MMD estimates as effect sizes, enabling pairwise model/provider comparisons and more nuanced interpretation of deviations.; Useful open-source contribution: code and a large dataset of 1.1M completions should facilitate follow-up work and reproducibility.; The appendices are extensive and include robustness checks such as permutation-based p-values, asymmetric sampling costs, and comparisons to approximate goodness-of-fit tests.; The discussion of character-space comparison for models/APIs with different tokenizers is pragmatic and broadens applicability.

Weaknesses: The main proposed Hamming MMD is only a pseudometric, so equality in this feature space does not imply equality of the underlying distributions; this limits the semantic strength of non-rejection.; The empirical evaluation is strong but largely heuristic: there is limited theory characterizing power, consistency under the chosen prompt-conditioned setup, or when the Hamming kernel is preferable to alternatives.; The prompt distributions used in simulations are somewhat narrow and synthetic relative to many real deployments; generalization to broader user workloads remains uncertain.; The composite-null audit procedure in Section 5 is conservative and may substantially reduce power, making interpretation of non-flagged endpoints less clear.; Several API comparisons are conducted in character space because tokenization/logprobs are unavailable; while practical, this may conflate tokenizer/rendering effects with deeper distributional differences.; The decision to average rejection rates over ten repeated tests and threshold at 0.5 is operationally reasonable but somewhat ad hoc and not fully justified statistically.; The paper identifies deviations in commercial APIs but cannot usually attribute them causally to specific mechanisms (e.g., quantization, caching, decoding bugs, watermarking, or prompt-template differences).; Correlation between MMD and downstream task accuracy is only moderate, so the practical significance of some detected shifts may be ambiguous for end users.

Methodological Flaws: There is a scientific logic error in Appendix A.1: the paper states the triangle inequality as 'MMD(P1,P3) = MMD(P1,P2) + MMD(P2,P3) for any P1,P2,P3'. Equality is false in general; at most one expects an inequality for the metric induced by the RKHS norm. Since Equation (3) defines squared MMD, even the usual triangle inequality does not directly hold for the squared quantity. This is a genuine mathematical flaw in the exposition/proof discussion.; Relatedly, the paper inconsistently treats MMD_k in Equation (3) as the squared RKHS distance while later referring to it as a metric/pseudometric obeying triangle inequality. Squared distances are generally not metrics, so the metric claims need correction or reformulation in terms of sqrt(MMD).; The p-value computation by simulating the null from a finite pre-collected dataset sampled with replacement (Appendix B.1/B.2) is only an approximation to sampling from the true reference distribution. This may slightly distort nominal Type-I error guarantees, especially when the empirical reference dataset is limited or reused heavily.; The audit pipeline includes several practical choices that weaken formal validity guarantees: testing in character space, repeated testing over ten samples, and classifying endpoints by average rejection rate >= 0.5. These choices are sensible operationally but are not derived from a formal hypothesis-testing framework, so the final endpoint-level false positive/negative behavior is not rigorously characterized.; The comparison to goodness-of-fit tests is not fully fair because the proposed one-sample tests are approximated by evaluating probabilities only on observed samples, introducing acknowledged bias. As presented, these results should not be interpreted as definitive evidence that two-sample testing is superior when true probability access is available.; Potential confounding from prompt-template mismatch is nontrivial: Appendix B notes that the authors changed the local template for Llama-3.1 to match observed API token counts. This is pragmatic, but it underscores that some detected differences could arise from undocumented system-prompt/chat-template discrepancies rather than model-weight or inference-stack changes per se.
